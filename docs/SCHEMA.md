# JISO Unified Polymorphic Configuration Schema (v0.3.0)

JISO uses a flat array polymorphic JSON schema for defining ISO8583 transactions, data pools, stateful test scenarios, and embedded mock server response routes.

## Configuration Item Types (`"type"`)

Each item in the root JSON array specifies a `"type"` discriminator:
- `"transaction"` (default if omitted): Standalone message definitions or reusable base templates.
- `"dataset"`: Relational data pools (e.g. card pools, test accounts) referenced across steps and transactions.
- `"scenario"`: Multi-step execution flows with dataset variable interpolation, response state extraction, and field assertions.
- `"mock_route"`: Server response matching and edge disruption rules for the embedded mock server.

---

## 1. Transaction Definition (`"type": "transaction"`)

```json
{
  "type": "transaction",
  "name": "Sign On",
  "description": "Network Management: Sign On (0800)",
  "dataset_name": "card_pool",
  "fields": {
    "0": "0800",
    "7": "auto",
    "11": "auto",
    "37": "auto",
    "70": "1"
  }
}
```

### Autogenerated Field Reserved Keywords
Field values in transaction definitions or scenario steps can use reserved keywords for dynamic runtime value generation:
- `"auto"`, `"$auto"`: Automatically populates field based on spec (DE 7 = Transmission Date/Time, DE 11 = STAN, DE 12 = Local Time, DE 13/15/17 = Local Date, DE 37 = RRN).
- `"STAN"`, `"$STAN"`, `"GEN_STAN"`: Generates atomic thread-safe System Trace Audit Number (DE 11).
- `"RRN"`, `"$RRN"`, `"GEN_RRN"`: Generates 12-digit Retrieval Reference Number (DE 37).
- `"datetime"`, `"$datetime"`: Generates MMDDhhmmss transmission timestamp (DE 7).
- `"date"`: Generates MMDD current date.
- `"time"`: Generates hhmmss current time.
- `"random"`, `"$random"`: Generates random value matching field spec length.

## 2. Dataset Definition (`"type": "dataset"`)

```json
{
  "type": "dataset",
  "name": "card_pool",
  "data": [
    {
      "PAN": "4111111111111111",
      "Expiry": "2612"
    },
    {
      "PAN": "4222222222222222",
      "Expiry": "2701"
    }
  ]
}
```

---

## 3. Scenario Definition (`"type": "scenario"`)

```json
{
  "type": "scenario",
  "name": "Purchase Flow",
  "description": "Sign On followed by Card Purchase with Auth ID Extraction",
  "dataset_name": "card_pool",
  "steps": [
    {
      "name": "Sign On Step",
      "use_transaction_id": "Sign On",
      "validate": [
        {
          "field": "39",
          "expect": "00"
        }
      ]
    },
    {
      "name": "Purchase Step",
      "use_transaction_id": "Purchase",
      "fields": {
        "2": "{{data.PAN}}",
        "14": "{{data.Expiry}}"
      },
      "extract": {
        "AuthId": "38"
      },
      "validate": [
        {
          "field": "39",
          "expect": "00"
        },
        {
          "field": "38",
          "exists": true
        }
      ]
    }
  ]
}
```

## 4. Embedded Mock Route (`"type": "mock_route"`)

```json
{
  "type": "mock_route",
  "name": "Sign On Auto Approval",
  "match_mti": "0800",
  "match_de3": "000000",
  "echo_fields": [7, 11, 37],
  "response_mti": "0810",
  "response_fields": {
    "39": "00"
  },
  "delay_ms": 10,
  "drop_connection": false
}
```
